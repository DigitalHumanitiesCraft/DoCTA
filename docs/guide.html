    Working with DoCTA

    To edit, you start DoCTA on your own computer. You work in the browser and save your changes in the cloned project folder. Annotating and saving work only in this local working edition. The public website is a read-only view: corrections made there remain a browser draft that can only be exported.

    The local working edition is running. Open the Thaur inventory or choose another document under Sources.

    Set upStartWorkBack up

    One-time setup

    1. Create a GitHub account if you do not have one, and send your user name to the project support.
    2. Install GitHub Desktop and sign in. Download the project via File → Clone Repository → URL: 
      https://github.com/DigitalHumanitiesCraft/DoCTA.git
      Choose a location and click Clone. Clone the repository; do not create a fork.
    3. Install Visual Studio Code. Open the downloaded DoCTA folder via File → Open Folder, then choose Terminal → New Terminal.

    The file requirements.txt is already in the DoCTA folder. It lists the required Python packages with their versions. Install them with the following commands for your operating system. Enter each line separately and wait for it to finish. This requires an internet connection.

    Windows

    Install the Python Install Manager of the Python Software Foundation from the Microsoft Store. Then reopen the VS Code terminal and run:

    py install 3.14
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

    macOS

    Install Python 3.14 from python.org. Then reopen the VS Code terminal and run:

    python3.14 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt

    The packages are then installed in .venv inside the DoCTA folder. Continue with Start.

    Start at every working session

    First fetch the latest version from GitHub. In GitHub Desktop, select the DoCTA repository, click Fetch origin and then Pull origin if it appears. If GitHub Desktop reports conflicting changes, stop and contact the project support instead of discarding anything. If the update changed requirements.txt, run the pip install line from the setup again.

    Open the DoCTA folder in VS Code and start DoCTA in the terminal. On Windows:

    .\.venv\Scripts\python.exe pipeline/local_editor.py --open-browser

    On macOS:

    ./.venv/bin/python pipeline/local_editor.py --open-browser

    DoCTA opens in the browser. Keep the terminal open. This Python server is what makes saving possible. The VS Code extension Live Server is not needed for this. Source images may require internet access.

    Working with your sources

    Open a document under Sources. Image and transcription stand side by side. Whole page resets the image area.

    Correcting the text

    Choose Edit, enter your initials and click a line. Correct it against the image. Enter accepts the draft; only Save changes stores it permanently. Reload to check. You correct a wrong saved reading with a further saved change. Switch Edit off again afterwards.

    Annotating persons and terms

    Annotation is available only in the local working edition started above, not on the public website.

    1. Select a passage within one text line. Choose Person, Term, Place or Date. If the selection field does not appear, use Annotate selection.
    2. Enter your initials. For persons, terms or places, search for a matching entry or choose New register entry and save it with Save entry. You decide every assignment yourself.
    3. Then choose Save occurrence. The register entry describes the person or the term; the occurrence links it to this passage of the text. That is why both save steps are needed.
    4. Under Index you find your persons, places and terms again. The occurrences lead back to the text. Dates are edited directly at their passage.

    Click an existing mark to change it or to delete it with Remove occurrence. The source text remains unchanged. After a text correction, check the affected annotations again.

    Backing up and finishing

    Save open text corrections and occurrences explicitly each time. Stop DoCTA in the terminal with Ctrl+C. Back up the whole project folder on a separate drive. Unsaved browser drafts are not part of the backup.

    Your edits initially remain on your computer. A Git commit records a local version. Only Push origin uploads it to the public repository. Agree beforehand which data may be published.

    The README explains exchange through GitHub, updates and recovery.

    If you have questions or see error messages, get in touch with the source, the page and the action you performed, ideally with a screenshot. Keep unsaved input separately before reloading.
