DoCTA

    Mit der Arbeitsedition arbeiten

    Mit DoCTA vergleichst du Quellenbilder und Transkriptionen, korrigierst Lesungen und baust deinen eigenen Personenindex sowie ein kontrolliertes Vokabular auf. Jede Zuordnung entscheidest du selbst. Arbeite mit den Quellen, die du untersuchen möchtest. Das Personenbeispiel unten hilft dir bei Bedarf beim Einstieg.

    Diese Website kannst du direkt ansehen. Zum Bearbeiten lädst du DoCTA auf deinen Rechner und öffnest dort die Startdatei. Sie startet das Programm und öffnet DoCTA im Browser. Deine Änderungen werden dann im heruntergeladenen Projektordner gespeichert. Richte es unten ein und öffne danach im gestarteten DoCTA oben Anleitung.

    Du liest die Anleitung in der lokalen Arbeitsedition. Thaur, Seite 1, in dieser Arbeitsedition öffnen. Über Anleitung kommst du wieder hierher.

    Einmalig einrichten

    Du legst eine Kopie des Projekts mit GitHub Desktop auf deinem Rechner an. Dieser Vorgang heißt Klonen. Danach installierst du einmalig uv und öffnest die DoCTA-Startdatei. uv ist ein Installationsprogramm, das sich um die passende Python-Version und die benötigten Zusatzpakete kümmert. Später genügt die Startdatei. Visual Studio Code ist zum Arbeiten mit DoCTA nicht erforderlich.

    GitHub-Konto und Projektordner

    1. Falls du noch kein GitHub-Konto hast, lege eines bei GitHub an. Teile der Projektbetreuung deinen Benutzernamen mit und nimm die Einladung zur Mitarbeit an. Das öffentliche Repository kannst du bereits vor der Einladung klonen. Zum direkten Hochladen brauchst du Schreibzugriff.
    2. Installiere GitHub Desktop und melde dich mit deinem GitHub-Konto an. Richte im Einrichtungsdialog deinen Namen und die gewünschte E-Mail-Adresse für die Versionsgeschichte ein.
    3. Wähle in GitHub Desktop File → Clone Repository → URL. Trage https://github.com/DigitalHumanitiesCraft/DoCTA.git ein. Wähle unter Local Path einen neuen Ordner und klicke Clone. Damit erhältst du die Projektdateien einschließlich ihrer Versionsgeschichte.
    4. Öffne den geklonten Ordner über Repository → Show in Explorer unter Windows oder Show in Finder auf macOS. Arbeite später immer in diesem Ordner.

    Die Installationsbefehle stammen aus der offiziellen uv-Anleitung. uv erklärt auch die automatische Python-Einrichtung.

    DoCTA unter Windows starten

    1. Öffne über das Startmenü PowerShell. Füge den folgenden offiziellen Installationsbefehl ein und drücke Enter. Er lädt uv herunter und installiert es für dein Benutzerkonto. 
      powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
    2. Öffne im geklonten Projektordner start-editor.cmd mit einem Doppelklick. Beim ersten Start richtet uv Python und die Zusatzpakete ein, soweit sie noch fehlen.

    DoCTA auf macOS starten

    1. Öffne mit Spotlight die Anwendung Terminal. Füge den folgenden offiziellen Installationsbefehl ein und drücke Enter. Er lädt uv herunter und installiert es für dein Benutzerkonto. 
      curl -LsSf https://astral.sh/uv/install.sh | sh
    2. Öffne im geklonten Projektordner start-editor.command mit einem Doppelklick. Beim ersten Start richtet uv Python und die Zusatzpakete ein, soweit sie noch fehlen. Falls die Datei nicht startet, tippe im Terminal bash mit einem Leerzeichen, ziehe die Startdatei aus dem Finder in das Terminal und drücke Enter.

    Beim ersten Start werden die Programmpakete geladen. Danach öffnet sich DoCTA im Browser mit einer Adresse, die mit http://127.0.0.1: beginnt. Diese Adresse führt zu deinem eigenen Rechner. Lass das zusätzlich geöffnete Terminalfenster während der Arbeit offen. Wähle eine Quelle und beginne mit der Bearbeitung. Über Anleitung kannst du jederzeit nachschlagen. Quellenbilder können weiterhin Internetzugriff benötigen.

    Wenn du bereits Visual Studio Code verwendest

    Öffne den DoCTA-Ordner in VS Code und wähle Terminal → New Terminal. Nach der uv-Installation startet dieser Befehl dieselbe Arbeitsedition wie die Startdatei:

    uv run --locked python pipeline/local_editor.py --open-browser

    Die Erweiterung Live Server und der Befehl python -m http.server zeigen statische Webseiten an. Die DoCTA-Funktionen zum Speichern von Korrekturen und Annotationen benötigen den eigenen Python-Server, den die Startdatei oder der Befehl oben startet. Ein zusätzlicher Live Server ist dafür nicht nötig.

    Der Start per Doppelklick und Finder auf macOS ist noch nicht praktisch auf einem Mac geprüft.

    Eine Person anlegen und wiederfinden

    Ein Registereintrag beschreibt eine Person in deinem Index. Eine Fundstelle hält fest, wo diese Person im Quellentext erwähnt wird. Ein Eintrag kann mehrere Fundstellen haben. Deshalb speicherst du beim erstmaligen Anlegen zuerst den Eintrag und anschließend seine Fundstelle.

    1. Öffne in der lokalen Anwendung Quellen, suche nach A 049.1 und öffne das Inventar des Schlosses Thaur. Wähle Seite 1. Du siehst das Quellenbild neben der Transkription. Die Textquelle ist Inventaria.
    2. Suche in der Transkription durch Hannsen Ramung,. Vergleiche die Stelle mit dem Bild. Über Ganze Seite kehrst du nach dem Zoomen zur vollständigen Bildansicht zurück.
    3. Markiere nur Hannsen Ramung, ohne das Komma. Wähle im eingeblendeten Feld Person. Falls das Feld nicht erscheint, nutze nach dem Markieren Auswahl annotieren.
    4. Trage unter Dein Kürzel deine Initialen ein. Wähle Neuer Registereintrag. Als Bezeichnung kannst du zunächst den Quellenwortlaut Hannsen Ramung verwenden. Weitere Schreibweisen und eine Notiz sind optional. Damit ist noch keine Gleichsetzung mit einer Person aus anderen Quellen getroffen.
    5. Wähle Eintrag speichern. Der neue Eintrag erscheint als Zuordnung der ausgewählten Textstelle. Wähle anschließend Fundstelle speichern und warte auf die Bestätigung.
    6. Lade die Seite neu. Der Name ist weiterhin als eigene Annotation markiert. Öffne oben Index und suche nach deiner Bezeichnung. Wähle den Eintrag und klicke unter Fundstellen auf die Erwähnung. Du gelangst zur annotierten Quellenstelle zurück.

    Falls der Eintrag bereits existiert, suche ihn im Feld Eintrag suchen und wähle ihn unter Zuordnung. Verwende ihn nur, wenn du dieselbe Person meinst. Eine offene Identifizierung kannst du mit Noch nicht zugeordnet und einer Notiz speichern.

    Eine Lesung korrigieren

    Korrigiere nur, wenn du die neue Lesung am Bild begründen kannst. Für das Personenbeispiel oben ist keine Textänderung erforderlich.

    1. Wähle Bearbeiten und trage dein Kürzel ein. Klicke auf die betreffende Textzeile.
    2. Bearbeite die Lesung. Enter übernimmt sie zunächst als ungespeicherten Entwurf. Escape bricht die offene Zeileneingabe ab.
    3. Wähle Änderungen speichern und warte auf die Bestätigung. Lade die Seite neu und prüfe die gespeicherte Lesung.
    4. Klicke erneut auf Bearbeiten, um die Textbearbeitung auszuschalten, bevor du weitere Stellen annotierst.

    Ist eine gespeicherte Korrektur falsch, bearbeite dieselbe Zeile erneut und speichere die berichtigte Lesung. Die vorherige Bearbeitung bleibt im Verlauf erhalten. Änderungen verwerfen entfernt nur ungespeicherte Änderungen der aktuellen Seite. Es setzt keine gespeicherte Korrektur zurück.

    Begriffe, Orte und Datumsangaben

    Begriffe und Orte legst du wie Personen an. Wähle beim Markieren die passende Art. Für dein kontrolliertes Vokabular bestimmst du die Bezeichnung und verwendest denselben Eintrag an weiteren passenden Stellen. Eine Begriffszuordnung besagt noch nicht, dass zwei Erwähnungen denselben historischen Gegenstand meinen. Handlungen kannst du bei Bedarf ebenfalls als eigene Begriffe erfassen.

    Bei Datumsangabe kannst du ein Datum oder einen Zeitraum ergänzen und Unsicherheit festhalten. Die Quellenform bleibt erhalten. Kalenderangaben werden nicht automatisch umgerechnet. Personen, Orte und Begriffe erscheinen im Index. Datumsangaben bearbeitest du an ihrer Textstelle.

    Klicke auf eine bestehende Markierung, um ihre Zuordnung oder Notiz zu ändern. Fundstelle entfernen entfernt diese Annotation, der Quellentext und der Registereintrag bleiben erhalten. Unter Änderungsverlauf bleibt die Bearbeitung nachvollziehbar.

    Speichere Textkorrekturen vor dem Annotieren. Eine Auswahl bleibt innerhalb einer Textzeile. Ändert sich der Wortlaut einer bereits annotierten Stelle, muss ihre Zuordnung erneut geprüft werden. Ein geschlossenes Feld mit offenen Eingaben erreichst du über Annotation fortsetzen.

    Arbeit sichern und später fortsetzen

    1. Speichere offene Textkorrekturen mit Änderungen speichern. Speichere bearbeitete Registereinträge und Fundstellen jeweils mit ihrer eigenen Schaltfläche. Warte auf die Bestätigungen.
    2. Wechsle in das Terminalfenster und drücke Ctrl+C, unter Windows Strg+C. Damit beendest du das lokale Programm.
    3. Kopiere den gesamten Arbeitsordner auf ein separates Sicherungslaufwerk. Benenne die Kopie mit dem Sicherungsdatum und bewahre die vorherige Sicherung auf. Eine Kopie auf derselben Festplatte schützt nicht vor deren Ausfall.
    4. Beim nächsten Mal öffnest du die Startdatei in deinem bisherigen Arbeitsordner. Deine gespeicherten Lesungen und Annotationen sind wieder verfügbar.

    Zum Wiederherstellen auf demselben Betriebssystem kopierst du den gesicherten Ordner an einen neuen Ort, lässt den bisherigen Ordner bestehen und startest aus der Kopie. Prüfe dort eine bekannte Korrektur und eine Fundstelle im Index. Vor einem Wechsel auf einen anderen Rechner stimme die Übernahme deiner lokalen Bearbeitungen mit der Projektbetreuung ab. Ein neuer Klon enthält nur die bereits auf GitHub gespeicherten Stände.

    Die Speicherung dokumentiert Kürzel, Zeitpunkt und Änderungen. Deine Arbeit wird dadurch nicht an andere Rechner übertragen oder veröffentlicht. Ungespeicherte Browserentwürfe und offene Formulare sind in der Ordnersicherung nicht enthalten.

    Eine neue Programmversion übernehmen

    Du übernimmst Updates mit GitHub Desktop in deinen bestehenden Projektordner. Bei Änderungen am Datenformat folge zusätzlich der jeweiligen Umstellungsanleitung.

    1. Speichere deine Arbeit in DoCTA, beende das Programm und sichere den Ordner. Halte die lokalen Änderungen mit einem Commit fest.
    2. Öffne in GitHub Desktop das DoCTA-Repository. Prüfe unter Current Branch, dass du auf dem vereinbarten Branch arbeitest. Ein Branch ist ein benannter Entwicklungsstand.
    3. Fetch origin prüft, ob auf GitHub neue Änderungen vorliegen. Falls angeboten, übernimmt Pull origin diese in deinen aktuellen Branch. Änderungen aus anderen Branches werden dadurch nicht übernommen. Wenn du auf einem eigenen Branch arbeitest, stimmt ihr die Übernahme von Programmupdates aus main gesondert ab.
    4. Meldet GitHub Desktop einen Konflikt oder sind noch unklare lokale Änderungen vorhanden, unterbrich die Übernahme und melde dich mit der Fehlermeldung. Verwirf keine Forschungsdaten, um ein Update zu erzwingen.
    5. Starte DoCTA nach einem erfolgreichen Update über die Startdatei. Prüfe eine bekannte Korrektur und eine Fundstelle samt Änderungsverlauf, bevor du weiterarbeitest.

    Export und technische Vertiefung

    Im Index lädt Register als JSON exportieren die Einträge, Fundstellen und ihren Verlauf als Datendatei herunter. Diese Datei ersetzt keine vollständige Sicherung der Textkorrekturen. Der eigene Index ist bisher nicht in die automatisch erzeugten TEI- und Graph-Ausgaben eingebunden.

    Die README erklärt die Speicherorte und Versionierung.

    Mit GitHub Desktop zusammenarbeiten

    Git hält Versionen deiner Dateien fest. GitHub stellt ein Repository, also den gemeinsamen Projektordner samt Versionsgeschichte, im Internet bereit. GitHub Desktop bedient Git über ein Programmfenster. DoCTA speichert deine Bearbeitungen zunächst nur im lokalen Projektordner. Das Hochladen ist ein eigener Schritt.

    Speichern und einen Versionsstand festhalten

    1. Speichere in DoCTA alle offenen Bearbeitungen und beende das Programm. Öffne danach in GitHub Desktop das passende Repository.
    2. Unter Changes siehst du die geänderten Dateien. Wähle die Dateien deiner Bearbeitung aus. Zu Textkorrekturen gehören die geänderten Dateien unter pipeline/pages und die zugehörigen Ereignisse unter pipeline/reviews. Der eigene Index liegt unter pipeline/registry. Bei unklaren weiteren Dateien frage nach, bevor du sie übernimmst oder verwirfst.
    3. Trage in Summary eine kurze Beschreibung deiner Arbeit ein. Klicke Commit to …, wobei der Button den aktuellen Branch nennt. Der Commit hält diesen Stand auf deinem Rechner fest. Die Ordnersicherung bleibt zusätzlich sinnvoll.

    Änderungen austauschen

    Das DoCTA-Repository ist öffentlich. Ein Push macht die hochgeladenen Dateien samt Verlauf für andere sichtbar, auch auf einem zusätzlichen Branch. Stimme deshalb vor dem ersten Hochladen ab, welche Forschungsdaten veröffentlicht werden dürfen und auf welchem Branch ihr arbeitet. Ein Branch ist ein benannter Entwicklungsstand. Änderungen unter docs/ auf main werden außerdem auf GitHub Pages veröffentlicht.

    1. Wenn der Austausch vereinbart ist, lädt Push origin die lokalen Commits auf GitHub. Ein neuer, vereinbarter Branch kann zunächst Publish branch anzeigen. Ohne diesen Schritt bleiben die Commits auf deinem Rechner. Eine Schreibberechtigung allein löst keine Übertragung aus.
    2. Zum Übernehmen neuer Änderungen folge dem Abschnitt Eine neue Programmversion übernehmen.

    Die Menüschritte folgen der GitHub-Dokumentation zum Klonen, zu Commits und zum Synchronisieren. Dieser Ablauf wurde anhand der Dokumentation geprüft. Die Bedienung von GitHub Desktop auf dem Rechner der Editorin steht noch aus.

    Wenn etwas nicht klappt

    • Fehlt Änderungen speichern, öffne Bearbeiten und prüfe, ob du im lokal gestarteten DoCTA-Fenster arbeitest. Die öffentliche Website kann deine Projektdateien nicht speichern.
    • Meldet die Startdatei, dass uv fehlt, wiederhole dessen Installation und starte die Datei danach erneut. Bleibt der Fehler bestehen, halte die Meldung für eine Rückfrage fest.
    • Öffnet sich die Seite nicht, prüfe das Terminalfenster. Bei einem bereits belegten Anschluss beende deinen vorherigen DoCTA-Start mit Ctrl+C und starte aus dem gewünschten Arbeitsordner erneut.
    • Bei einem Speicherkonflikt kopiere deine ungespeicherte Lesung zunächst in eine separate Textdatei. Lade dann den gespeicherten Stand neu und gleiche die Lesungen ab. Verwirf einen Entwurf erst, wenn du die Eingabe gesichert hast.
    • Bei fehlenden Bildern prüfe die Internetverbindung. Manche Quellen haben noch nicht alle benötigten Bildadressen. Eine dokumentierte Seitenzahl bedeutet deshalb nicht, dass alle Bilder verfügbar sind.

    Für eine Rückmeldung genügen Quelle und Seite, die ausgeführte Handlung sowie das erwartete und das beobachtete Ergebnis. Ein Screenshot kann die betreffende Stelle zeigen.
