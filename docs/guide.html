    Mit der Arbeitsedition arbeiten

    DoCTA zeigt Quellenbilder neben ihren Transkriptionen. Du kannst Lesungen korrigieren, Textstellen annotieren und dabei dein eigenes Personenregister und kontrolliertes Vokabular aufbauen. Welche Stellen zusammengehören und welche Begriffe passen, entscheidest du selbst.

    Website und lokale Arbeitsedition

    Die öffentliche Website auf GitHub Pages dient zum Lesen und Vergleichen. Textkorrekturen lassen sich dort als Browserentwurf bearbeiten und als JSON-Datei exportieren. Sie werden dadurch noch nicht in die Projektdateien übernommen.

    Für dauerhaft gespeicherte Korrekturen, eigene Annotationen und den Index startest du die Arbeitsedition auf deinem Rechner. Die Adresse beginnt dann mit http://127.0.0.1. Deine Änderungen bleiben in deinem Projektordner. Quellbilder können auch bei lokaler Nutzung eine Internetverbindung benötigen. Für Lesen, Korrigieren und Annotieren brauchst du keinen LLM-API-Key.

    Quellenübersicht öffnen

    Lokal starten

    1. Installiere einmalig uv nach der Anleitung für dein Betriebssystem. Es richtet die benötigte Python-Umgebung ein.
    2. Hole das DoCTA-Repository mit GitHub Desktop auf deinen Rechner. Alternativ kannst du auf GitHub unter Code das ZIP herunterladen und vollständig entpacken. Arbeite danach in diesem Projektordner.
    3. Öffne unter Windows start-editor.cmd, unter macOS start-editor.command. Beim ersten Start werden die benötigten Pakete geladen. Dafür ist eine Internetverbindung erforderlich.
    4. Der Browser öffnet die lokale Arbeitsedition. Lass das zugehörige Terminalfenster während der Arbeit geöffnet.

    Falls macOS die Startdatei nicht ausführt, öffne ein Terminal im Projektordner und führe bash start-editor.command aus. Die technische Einrichtung ist in der README beschrieben. Der Start auf macOS muss noch auf einem Mac praktisch geprüft werden.

    Erster Durchgang

    1. Öffne in deiner lokalen Arbeitsedition das Inventar des Schlosses Thaur. Titel, Signatur und Datum stehen über dem Arbeitsbereich. Die Transkriptionsherkunft ist beim Text angegeben.
    2. Vergleiche eine kurze Passage mit dem Bild. Die Ansicht beginnt mit dem ganzen Bild. Vergrößere eine Stelle und kehre mit Ganze Seite zur Übersicht zurück.
    3. Wähle Bearbeiten, trage dein Kürzel ein und klicke eine Textzeile an. Ändere nur eine Lesung, die du am Bild begründen kannst. Enter übernimmt die Eingabe zunächst in den Browserentwurf.
    4. Wähle Änderungen speichern und warte auf die Bestätigung. Lade die Seite neu. Die gespeicherte Korrektur muss wieder erscheinen.
    5. Markiere eine Stelle, ordne sie einem eigenen Registereintrag zu und speichere die Fundstelle. Öffne danach den Index und folge der Fundstelle zurück zum Text.

    Das Silberinventar zeigt zusätzlich eine maschinelle Ausgangstranskription. Fehlende Bildreferenzen begrenzen dort den zugänglichen Umfang. Ein Katalogeintrag oder eine dokumentierte Seitenzahl bedeutet noch nicht, dass sämtliche Bilder im Viewer vorliegen.

    Eigene Annotationen und Register

    Speichere zuerst deine Textkorrekturen. Markiere dann den Wortlaut innerhalb einer Zeile. Wähle Person, Begriff, Ort oder Datumsangabe. Du erreichst die Auswahl auch mit Rechtsklick, über Auswahl annotieren oder mit Alt+A.

    Bei Personen, Orten und Begriffen kannst du einen vorhandenen Eintrag suchen oder einen neuen anlegen. Eine bevorzugte Bezeichnung genügt zum Beginn. Weitere Schreibweisen und eine Notiz helfen später beim Wiederfinden und Unterscheiden. Gleiche Namen werden nicht automatisch zusammengeführt. Noch nicht zugeordnet lässt eine Fundstelle mit offener Identifizierung bestehen.

    Speichere einen neuen Registereintrag und anschließend die Fundstelle. Erst die gespeicherte Fundstelle verbindet den Eintrag mit dem ausgewählten Quellenwortlaut. Ein Klick auf eine bestehende Markierung öffnet ihre Bearbeitung. Du kannst die Zuordnung ändern oder die Annotation entfernen. Der Quellentext bleibt dabei erhalten, und die Änderung wird dokumentiert.

    Deine selbst angelegten Begriffe bilden das kontrollierte Vokabular. Du bestimmst ihre Bedeutung und Anwendung. Handlungen kannst du bei Bedarf ebenfalls als eigene Begriffe erfassen. Dafür gibt es keine gesonderte Ereignisannotation und kein vorgegebenes Vokabular.

    Datumsangaben behalten den Quellenwortlaut. Eine normalisierte Datierung, ein Zeitraum und eine Unsicherheit sind optionale Ergänzungen. Historische Kalenderangaben werden nicht automatisch umgerechnet.

    Der Index zeigt deine gespeicherten Personen, Orte und Begriffe mit ihren Fundstellen. Die Suche berücksichtigt Bezeichnungen, Schreibweisen und Notizen. Über Register als JSON exportieren erhältst du Einträge, Zuordnungen und deren Verlauf als Datei.

    Speichern, wiederaufnehmen und sichern

    Gespeicherte Textkorrekturen halten die vorherige und die neue Lesung mit Kürzel und Zeitpunkt fest. Die ursprüngliche Transkription bleibt erhalten. Eigene Annotationen haben ebenfalls einen Änderungsverlauf. Wenn sich ihr Quellentext ändert, muss die Fundstelle erneut geprüft werden.

    Textkorrekturen und Annotationen haben eigene Speicheraktionen. Ein geschlossenes Annotationsfeld kann noch einen Entwurf enthalten, den du über Annotation fortsetzen wieder öffnest. Änderungen verwerfen entfernt ungespeicherte Textänderungen der aktuellen Seite. Bereits gespeicherte Änderungen bleiben bestehen.

    Speichere vor dem Beenden alle bearbeiteten Felder. Danach kannst du den Server mit Ctrl+C im Terminal stoppen. Beim nächsten Start öffnest du dieselbe Startdatei und arbeitest im selben Projektordner weiter.

    Eine gespeicherte Änderung ist noch kein Git-Commit und keine Veröffentlichung. Mit GitHub Desktop kannst du die vorgesehenen geänderten Dateien prüfen und lokal committen. So bleibt ein versionierter Stand erhalten. Eine separate Sicherung des Projektordners schützt vor dem Verlust des Rechners. Bewahre bei einem ZIP-Download insbesondere deinen bisherigen Arbeitsordner auf und überschreibe ihn nicht mit einer neuen Kopie.

    Die eigenen Register werden derzeit separat als JSON exportiert. Sie sind noch nicht in die automatisch erzeugten TEI- und Graph-Ausgaben eingebunden. Frühere Schlagwortdateien bleiben erhalten, werden aber nicht automatisch in das eigene Vokabular umgewandelt.

    Speicherorte und Versionierung in der README

    Wenn etwas nicht klappt

    • Fehlen lokale Speicherfunktionen, prüfe die Browseradresse. Die öffentliche Website schreibt nicht in deinen Projektordner.
    • Öffnet sich die lokale Seite nicht, prüfe das Terminalfenster auf eine Fehlermeldung. Ein bereits laufender Editor wird vom Starter nicht beendet.
    • Bei einem Speicherkonflikt halte deine Eingabe fest, lade den gespeicherten Stand neu und gleiche die Lesungen ab. Verwirf einen Entwurf nicht allein, um die Meldung loszuwerden.
    • Bei fehlenden Bildern prüfe die Internetverbindung. Manche Quellen haben noch nicht alle benötigten Bildadressen.

    Für eine Rückmeldung genügen Quelle und Seite, die ausgeführte Handlung sowie das erwartete und das beobachtete Ergebnis. Ein Screenshot kann die betreffende Stelle zeigen.
